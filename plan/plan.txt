RAG Enhancement Plan
====================

Current baseline
----------------
- Load one text file.
- Split the document into fixed-size character chunks.
- Embed chunks with sentence-transformers.
- Store vectors in FAISS.
- Retrieve the top five chunks for each question.
- Send the retrieved context to a local Ollama model.


Phase 1: Smarter Chunking
✅ Switch from raw character splits to word/paragraph splits.
-Add small overlaps so ideas don’t get cut off.
-Keep headings with their content.
✅ Success: Retrieved chunks feel natural and complete.

Phase 2: Cleaner Retrieval
-Normalize embeddings.
-Use cosine similarity in FAISS.
-Show similarity scores with results.
-Add a relevance threshold (skip weak matches).
✅ Success: Only strong, relevant chunks are returned.

Phase 3: Traceable Answers
-Store metadata (file, section, chunk ID).
-Include source info in context.
-Ask the model to cite which chunks it used.
✅ Success: Every answer points back to the document.

Phase 4: Reusable Index
-Add a function/command to build the FAISS index.
-Save index + metadata to disk.
-Load saved index at startup.
-Rebuild only when the source file changes.
✅ Success: Faster startup, no repeated embedding work.

Phase 5: Quick Evaluation
-Write 10–15 test questions (some inside doc, some outside).
-Note expected answers or sections.
-Run retrieval checks before model answers.
✅ Success: You can measure improvements consistently.

Optional Later
-Support multiple files.
-Add a FastAPI web UI.
-Add conversation history after single Q&A is stable.
-Try reranking only if FAISS search isn’t enough.

🎯 Recommended Order
-Smarter chunking.
-Cosine similarity + normalization.
-Relevance threshold.
-Metadata + citations.
-Saved index.
-Evaluation set.
